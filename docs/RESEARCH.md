# Models, Results, and Data Sources

## Chronological releases

| Measure | IEEE-CIS research | Synthetic Financial (PaySim) |
| --- | --- | --- |
| Model | LightGBM | XGBoost |
| Training rows | 410,601 | 4,784,775 |
| Validation rows | 85,303 | 1,279,261 |
| Holdout rows | 94,636 | 298,584 |
| Decision threshold | 0.74853243 | 0.91918761 |
| Holdout average precision | 0.1152 | 0.2872 |
| Holdout ROC-AUC | 0.7637 | 0.9154 |
| Fraud precision / recall | 15.54% / 23.22% | 24.76% / 31.44% |
| Fraud caught / missed | 762 / 2,520 | 815 / 1,777 |
| False alerts | 4,142 | 2,476 |
| Alerts per 1,000 vs. validation budget | 51.82 vs. 50 | 11.02 vs. 10 |

**IEEE-CIS.** On a chronological validation window, LightGBM outperformed XGBoost on average precision (0.1116 vs. 0.1035) with the same inputs. The release uses transaction amount, its fractional part, and product-code indicators. Identity, card aggregates, IDs, timestamps, and fraud labels are excluded at scoring time. Notebooks 01 and 02 contain the historical exploratory code, not the release pipeline. That earlier experiment reported XGBoost ROC-AUC 0.9630 on a random split; it is not comparable to the release holdout.

**PaySim.** The release uses amount and transaction type. All four balance fields and the simulator's existing rule flag are excluded; the simulated hour is used only for splitting. The older 12-feature model used balance fields affected by payout or cancellation and is retained only as historical research. Its reported 0.9651 PR-AUC is not the pre-authorization result. The newer model's thresholds and exact metrics are in the release report.

Both release thresholds were chosen on validation, not on the later holdout. Both leave most fraud undetected at the chosen operating points and exceed their respective validation alert budgets on the holdout. Scores are rankings, not calibrated probabilities, and the two datasets have different prevalences and definitions; do not interpret the table as a head-to-head comparison.

## Reproduce the research locally

1. From the [IEEE-CIS competition data page](https://www.kaggle.com/competitions/ieee-fraud-detection/data), obtain the files under its [competition rules](https://www.kaggle.com/competitions/ieee-fraud-detection/rules). Put the labeled `train_transaction.csv` at `data/raw/ieee_cis/train_transaction.csv`. The historical notebooks also use identity and competition test CSVs from the same folder.
2. From [Edgar Lopez-Rojas's PaySim dataset](https://www.kaggle.com/ealaxi/paysim1/metadata), place the CSV at `data/raw/synthetic_financial/synthetic_financial.csv` (older `cleaned_data.csv` is accepted).
3. Install [research dependencies](../requirements-research.txt), then run:

```bash
python -m src.train_ieee_release --build
python -m src.validate_synthetic_release
```

The IEEE-CIS research weights stay local. The trainer will not overwrite differing files belonging to a published manifest. To build a locally retrained package without changing those files, pass a new ignored location, for example `--manifest outputs/ieee_cis/manifest.json`, and supply that path with the scorer's `--release` option. Use a separate demo database before registering a differently trained version.
